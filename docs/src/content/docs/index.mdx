## What is Platform Manager?

Platform Manager is a **platform controller**: a system that takes [SCORE](https://score.dev) workload specifications as intent and resolves them into running infrastructure, without the controller itself ever having to understand what that infrastructure *means* to your organization.

The design rests on separating three roles:

<CardGrid stagger>
	<Card title="The controller" icon="rocket">
		Provides *mechanism*: matching, resolution, reconciliation, provisioning orchestration, and explainability. It never embeds organizational semantics.
	</Card>
	<Card title="The platform team" icon="setting">
		Provides *meaning*: organizational vocabulary, policies, resource definitions, and provisioning wiring for their organization.
	</Card>
	<Card title="The application team" icon="pencil">
		Provides *intent*: SCORE workload specifications and resource declarations expressed in the organization's own vocabulary.
	</Card>
</CardGrid>

## Design principles

- **Separate mechanism from meaning.** The controller matches, resolves, reconciles, and explains. Organizations define vocabulary, attributes, policies, implementations, and provisioning logic.
- **Intent before infrastructure.** Applications express intent; organizations define how intent maps onto infrastructure; infrastructure details stay implementation details.
- **Explainability is first-class.** Every resolution outcome — success, failure, pending — is traceable: why an implementation matched, why others didn't, and what context was used.
- **Constraint solving over inheritance.** Resolution is attribute/constraint-based, not hierarchy-based. The resolver never invents infrastructure; provisioning is a separate, downstream concern.
- **Order independence.** The system is level-triggered and reconciling — no rule depends on the order in which objects are applied.
